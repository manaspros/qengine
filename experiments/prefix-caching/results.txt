Lesson 26: prefix caching on vs off. Qwen2.5-1.5B-Instruct bf16, vLLM 0.32.0, RTX 5090, 2026-11-03.
Command: python run.py [e1|e2|e3a|e3b]   (raw vllm bench JSON in results/, results27b/)
Fresh server per config, warm-up with a different seed (cache holds no measured prefix), hit rate
from vllm:prefix_cache_{hits,queries}_total deltas. ONE run per config (no n=5): treat <5% as noise.

                      hit    TTFT p50   E2E p50

  Article (Qwen3-30B-A3B FP8, H100): 0 -> 89% hits = 1.82x. Ours: 3.19x. Amdahl back-solve:
  1/(1 - 0.887 f) = 3.19 -> f = 0.77 here vs ~0.5 in the article. At 256 in flight our 1.5B dense
  model is compute-bound in both phases, so time ~ tokens processed: f ~ 1024/(1024+256) = 0.8.
  TPOT falls 37.8 -> 11.9 ms because each decode step no longer shares its token budget with
  prefill chunks (chunked prefill mixes them into the same step).
